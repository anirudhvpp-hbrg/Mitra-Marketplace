# Mitra marketplace: product review, 14 November 2026

Verdict: the architecture holds up. The screens were about 80% of a finished product. Seventeen visible defects were fixed today and checked on screen. What still separates Mitra from LM Studio, Jan or Raycast is missing features, not polish: streaming answers, a list of past conversations, TwinMind's own meeting page, and search inside a PDF.

## 1. How it was reviewed

- A private copy ran on port 7431 with its own home folder, so your real log and Dropbox were not touched. Your 2-hour call kept running in the background throughout.
- Every screen was opened and used: welcome, Apps, Create, Memory, System, Markdown Reader, Mitra PDF, Anything to MD, Ask Mitra and TwinMind. Each was checked in light and dark, at 1366 px wide and at 375 px (phone).
- Real use: a Word file converted and saved; a PDF in page view and text view; a real question to Qwen3 0.6B, answered in about 5 s; a transcript run end to end through Gemma 3 1B into a memo in 73 s; the memo opened in the reader.
- Benchmark: LM Studio, Jan, Msty, Ollama's app, Pinokio, Raycast and PowerToys Command Palette, from each product's own documentation, with sources (section 5).
- Tests: the quick suite, 343 cases (18 of them need real models and were skipped).

## 2. The architecture, from first principles

| Decision | Holds? | Why |
|---|---|---|
| Each app is its own process on its own port; the launcher has no capabilities of its own | Yes | Nothing runs that is not open; measured at about 12 MB per app. Separation is enforced in `scope()`, not just by convention |
| One governor, one model at a time, a queue with questions ahead of long jobs | Yes | This is the right answer to a 1 GB ceiling. No benchmarked product queues across apps. LM Studio and Ollama just load a second model |
| Pages served from disk, logic in short-lived Python workers | Yes | UI changes need no rebuild. Stdlib only, so it still installs on Termux |
| A fresh random port every time an app started | **No (fixed)** | Each port is its own web origin, so the theme, the Ask Mitra conversation and the last folder were lost every time an app was reopened |
| The theme kept only in localStorage | **No (fixed)** | Same cause: choosing dark in one window did not carry to the others |

The binary was rebuilt (go vet passes for Windows and Linux). The 0.9.0 binary is kept at `cache\scratch\mitra-review\backup-original\`, with the original text of every file I edited.

## 4. Tests

The final quick run: **325 of 325 passed**, 18 skipped (they need real models), in 215 s. Report: `logs/tests/results/2026-11-14-195616.md`.

Before that final run, T343 failed in four full runs while your 2-hour call was being transcribed. It passed every time it ran alone. The final run passed with the call still going, so the cause is not fully pinned down. The case now waits up to 15 s and names any leftover process with its process id, so if it fails again the cause will be visible.

Not run: the full 26-minute suite with real models, and a real Chrome `--app` window on your desktop.

## 5. Against the established products

| Pattern | Who does it | Mitra |
|---|---|---|
| Visible memory cost and model state | LM Studio (loading means putting it in RAM), Jan ("Fits / May be slow / Won't fit"), Ollama (`ps`, unload after idle) | **Ahead**: a measured MB per model, a 1 GB ceiling, the queue shown on three screens |
| Everything local, in plain files | LM Studio (chats as JSON), Pinokio (one folder) | Equal: Markdown memos, a JSONL log |
| First run ends in a working result | Jan downloads a model, Msty offers three paths | Partly: the welcome screen, then icons; no model-setup path if `models/` is missing |
| Answers stream in | Raycast, LM Studio | **Behind**: the answer arrives all at once |
| Past conversations, searchable | LM Studio (folders), Msty, Raycast | **Behind**: one conversation only |
| Regenerate, edit and resend | LM Studio (keeps older versions), Msty, Raycast | **Behind** |
| Attach a file to a question | LM Studio, Ollama, Raycast | **Behind** in Ask Mitra (only the generic workspace can ask about a file) |
| Queue a follow-up while an answer is still coming | Raycast | Mitra already has the queue; the screen does not offer it yet |
| Launcher home: pinned and recent | PowerToys Command Palette, Raycast | Equal: recents and Ctrl+K; no pinning |

Sources: lmstudio.ai/docs/app/basics/chat, lmstudio.ai/blog/lmstudio-v0.3.0, jan.ai/docs/desktop/manage-models, docs.msty.app/getting-started/onboarding, docs.ollama.com/faq, manual.raycast.com/ai/ai-chat, learn.microsoft.com/en-us/windows/powertoys/command-palette/overview. Not verified from documentation: stop buttons in LM Studio, Jan and Msty; Ollama's own resource screen.

## 6. What remains, in the order I would do it (not built; your call)

1. **Ask Mitra: streaming, Stop and Regenerate.** llama-server already streams; the worker returns everything at once. This is the biggest gap in feel.
2. **Ask Mitra: a list of past conversations.** Plain JSON files in `~/.mitra`, as LM Studio does.
3. **TwinMind's own meeting page**: notes beside the transcript, each point linked to its line, play the recording from any line (INTERFACE-REVIEW items 1 to 4). Still the largest product gap.
4. **Mitra PDF: search with a results list, the PDF's outline, last page remembered.**
5. **Pin an app or a file to the top of the home screen.**
6. **A first-run check**: if a model is missing, say so on the welcome screen with the `models sync` step, instead of leaving it to the System page.

Seen by me: everything in sections 1 to 4. Not seen: the real Chrome app window, Explorer "Open with", a real drag from Explorer, a phone.
